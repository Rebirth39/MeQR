# 活跃统计

iOS 与 Android 共用 `/sync-v1/` 下的 MeQR 自有统计接口。`AppActivity` 读取本机现有同步凭证，再由 `ActivityReporter` 在启动、回到前台或关闭同步设置时自动上报，不另设统计授权弹窗、开关或停止入口。统计处理范围在隐私政策中说明。

同步卡片复用 profileId，由服务器以北京时间按每日记录去重，并从本月记录计算自然月月活。客户端仅缓存当天的成功回执，不保存“同步卡片本月已上报”状态。多设备共享一张卡片只计一份，多张卡片分别计数，因此这是活跃同步卡片数，不能称为去重人数。

没有同步凭证时，上报只包含当天日期和日／月是否需要加一，不带账号、安装或设备标识。客户端收到完整回执后在 UserDefaults 保存成功日期及月份。服务器只有汇总，无法从匿名每日总数去重得出月活，所以此路径需要本地月状态。丢失响应重试、重装、清除数据、多设备或切换同步状态可能重复，指标为未同步安装的近似活跃数，与同步卡片分开展示。

统计请求不包含卡片、Tag、二维码或图片内容，不修改同步文档或版本。同步凭证读取失败时跳过，不误用匿名路径。`ActivityReporter` 使用 actor 防止并发前台事件重复发起；请求失败在下次前台事件重试。

在线服务保留最近 62 个自然日的同步卡片明细，日／月汇总长期保留。删除云卡会删除对应明细，既有汇总保留。匿名汇总没有可定位的单次上报记录，不能承诺通过邮件删除某个匿名计数。备份限制见现行政策。

iOS 隐私 manifest 对用于 Analytics 的 User ID 和 Product Interaction 声明可能与现有同步资料关联，Tracking 为 false。发布前仍需人工更新 App Store Connect 的 App Privacy 表单，本轮没有提交表单或发布版本。不使用第三方 SDK，不增加 ATT 请求。

验证命令为 `python3 -m unittest Tests/test_activity_reporting.py -v`，使用真实 reporter 和模拟传输，不污染生产计数。服务端及 Android 的接口、运维和测试细节见 Android 工程 `docs/activity-statistics.md`。
