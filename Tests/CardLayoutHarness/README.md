# Card layout regression harness

Run `node Tests/CardLayoutHarness/generate.cjs` from the iOS project root, then test `CardLayout.xcodeproj` with scheme `CardLayoutHost` on an iOS simulator.

The isolated app uses current production cards, pager, models, QR generator and Tag renderer. It substitutes language settings and supplies temporary in-memory fixtures without accessing user data or submitting reports.

Tests check short-card whitespace, unchanged card coordinates when adding/removing a second card, horizontal paging, Tags below long info, and reaching the QR/platform controls at 320pt with larger text.

`testFlippingKeepsCardHeightAndOnlyLongInfoScrolls` checks shared front/back surface height, fixed card coordinates, identity sizing, bounded section spacing, and local scrolling with short, multiline, overflowing, and empty introductions at 384×560, 540×780, and 620×900pt portrait viewports. It captures the back layout for the spacious viewports. Run it with `-only-testing:LayoutTests/LayoutTests/testFlippingKeepsCardHeightAndOnlyLongInfoScrolls`. Set `CARD_LAYOUT_OUTPUT` to a directory under `Documents/TestsScreenshot` when generating the harness.

Run the full portrait fixture matrix on a 13-inch iPad simulator so the 900pt fixture fits inside the navigation safe area. The harness supports native iPhone and iPad presentation.

`testGlassCardRepeatedFlipsKeepHiddenFaceInactive` flips a frosted card with a real image backdrop six times in each direction, checks that only the visible face exposes controls, and verifies fixed endpoint coordinates and platform selection. `testOriginalFlipExpandsWithoutClippingItsTop` measures the actual native perspective bounds inside the production flip layout at eight angles, verifies the original height expansion, and captures the complete top edge. Run `python3 -m unittest Tests/test_card_flip.py -v` from the project root to check the reserved vertical space against projected corners at 721 angles across five card sizes.

`testCachedColorCode` reads an existing `record.json` fixture without recompressing its avatar. It checks the original JPEG, capacity, and exact color-layer roundtrip. Optional `ipad-screen.png` and `iphone-preview.png` fixtures must both decode to that same payload and avatar; any failure fails the test. Diagnostic color-symbol comparisons use the known fixture only to measure errors, not to supply data to the production decoder. Keep all user fixtures outside the repository. Check the result bundle's executed test count, not just the xcodebuild exit code.

`testAvatarRepair` uses a local `record.json` exchange-cache fixture placed in `CARD_LAYOUT_OUTPUT` (skips if absent). It checks compact sRGB JPEG compression against the original QR capacity and the 800-byte minimum, rejection of an impossible budget, valid JPEG decoding, color-layer byte roundtrip, and persisted avatar repair without changes to payload, credentials, fingerprint, online profile, event, or sync state. Cache fixtures contain private data and must stay outside the repository. Only offline color-layer JPEGs use metadata stripping; online avatar encoding is unchanged.

`testColorLayerRoundTrips` verifies avatar bytes/CRC across the current and September 29 legacy iOS generators/readers, Android palettes, rotated/mirrored images, and monochrome fallback. Generate into `CARD_LAYOUT_OUTPUT`, then export `android-color.png`, `android-legacy.png`, and `avatar.jpg` from the isolated Android `ColorLayerInstrumentation` app into that directory before running. It exports `ios-color.png` and `ios-payload.txt`; push them to the Android emulator at `/data/local/tmp/meqr-ios-color.png` and `/data/local/tmp/meqr-ios-payload.txt`, then rerun the Android instrumentation for the reverse direction. Each generator pads for its own capacity because the native encoders can choose different QR versions for the same text. Without fixtures this test skips. These are image-level tests, not physical screen-to-camera acceptance.
